# 文章内容提取

## 目标与模板

只提取来源内容、忠实翻译并整理公开资源。使用用户指定的模板；未指定时读取 [templates/article-template.md](../../../templates/article-template.md)，填充该模板。模板仅定义输出结构，提取规则在本文件中维护。

默认使用中文，保留模型名、算法名、关键术语、公式和引用标记。不添加个人理解、评价、推测、额外教程或研究建议。作者的解释可以整理，但应明确归属于作者。

## 来源与完整性

- 读取文章全文及可获取的附录，确认标题和版本。同一篇文章优先使用用户提供的版本，避免混用不同版本的结果和编号。
- PDF 的图、表和公式需要查看页面，不能仅依赖文本提取；可使用可用的 PDF 工具或技能。
- 只获取到摘要或部分内容时，明确标记提取范围，仍完成可提取部分，不用其他版本或背景知识补成完整笔记。
- 论文、附录、官方代码仓库和项目主页可作为来源。来自仓库或外部页面的补充注明来源及链接，不冒充论文内容。
- 区分“原文未说明”“未获取相关材料”和“未找到官方公开资源”。不要将未找到写成不存在。
- 提取时间使用实际执行时的日期、时间和时区。

## 摘要与引言

- 对用户提供的全文，提取完整摘要和引言，分别放入模板的原文与中文翻译部分。原文段落与译文段落一一对应，不缩写。
- 保留贡献列表、引用编号或作者—年份标记、脚注内容以及图表引用。纠正可核实的 PDF 断行与 OCR 错误，不改写原句。
- 翻译保留数字、否定、比较对象、不确定性和结论的适用条件；译者解释不混入正文。
- 对仅有链接、未由用户提供全文的受版权保护文章，遵守适用的引用与转换限制；若不能提供完整原文及全文翻译，在对应位置说明并提供允许的摘要，可请用户提供 PDF 或文本后完成，其他部分继续整理。

## 创新点与核心方法

- 完整覆盖作者在摘要、引言、方法和结论中明确提出的独立贡献，不限制数量。合并重复表述，保留作者限定，不把常规组件或自己的归纳认定为创新。
- 核心方法按文章实际逻辑组织，可自由添加小节，不强制固定模块、顺序或篇幅。充分保留理解原文方法所需的训练过程、目标、实现细节与推理过程。
- 保留重要公式、编号和原文符号定义。按文章实际内容提取技术设计；VLA-RL 文章可包含动作表示、RL 优化、奖励和数据交互等，不适用的要素不强行补齐。
- 方法、贡献和实验结论尽量标注可核实的章节、公式或图表位置，不编造定位信息。

## 图与实验结果

- 保留框架图、方法图及支撑主要结论的结果图表；不要只提供图片而丢失图注和正文说明。图注按允许范围保留原文与中文翻译，正文说明忠实整理。
- 图像来自原文，可做准确的页面裁剪，不重新生成或改画科学图。保存为随笔记交付的附件，用有效相对路径引用。
- 表格可使用清晰原图或准确转录。保留单位、指标方向、误差范围、表注、比较对象与条件。若节选，明确注明范围。
- 完整覆盖主要实验、消融及原文提供的泛化、效率等结果，记录作者报告的失败案例，不只收录有利结果。
- 区分作者报告的观察和作者据此提出的结论，不自行计算提升率或添加因果解释。模糊数字须回看原图，仍无法确认则注明，不能猜测。

## 数据集、框架与公开资源

- 数据集区分预训练、微调、RL 和评测用途；基础模型已使用的数据与本文直接使用的数据明确区分。记录原文给出的版本、子集和规模。
- 提取实际使用的基础模型、训练框架、仿真环境、评测基准与关键依赖，不把相关工作或对照模型误记为本文组件。
- 开源资源置于模板前部。优先从论文和项目主页确认官方 GitHub、权重、数据与文档，再按需补查和核验。
- 官方实现和第三方复现明确区分；仓库的存在不代表训练代码、权重和数据全部公开。按实际可核实的范围填写，不猜测 URL。

## 重要参考文献

- 收录支撑研究问题的核心工作、直接继承或改进的方法、基础模型、RL 算法、数据集、基准及主要对照方法的参考文献，不设固定条数。
- 保留原论文编号或作者—年份标记，核对标题、作者、年份和链接。
- “本文中的引用用途”只根据本文引用语境填写。没有阅读被引用文献时，不扩展说明其方法或结论。
- 能核实官方代码时提供 GitHub 链接；无法确认则不填造链接。
